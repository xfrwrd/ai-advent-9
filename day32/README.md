# Day 32 — автоматический code review

Ревьюер читает diff между двумя Git ref, подкладывает документацию и исходники из индекса того же коммита и просит локальную Qwen вернуть JSON. В отчёт попадает только то замечание, у которого файл и строка есть в diff, а цитата дословно найдена в diff или в приложенном контексте.

```text
python -m day32 --base main --head HEAD
    ↓
git diff, фиксированные аргументы, без shell
    ↓
изменённые файлы
    ↓
day31.retrieve по индексу этого коммита
    ↓
LocalLLMClient, think=false, qwen3:8b
    ↓
проверка file / line / evidence
    ↓
day32/reports/<время>-<sha>/review.md и findings.json
```

Модель не запускает команды, не правит файлы и не делает `git push`. Diff, README и код в промпте помечены как данные, а не как инструкции.

## Что переиспользовано

- Нарезка и SQLite: `day21/chunking.py`, `day21/index_store.py`.
- Эмбеддинги: `LocalHashEmbedder`, `local-token-hash-v1`.
- Поиск: `day31/retrieve.py` (`day22/retrieve.py` внутри). Правила отбора документов те же, что у Day 31: README, `docs`, `day*/README.md`, OpenAPI, если файл есть. `day31/README.md` и `day32/README.md` в индекс не входят.
- Модель: `day26/client.py`, `LocalLLMClient.ask(..., think=False)`. Отдельные `temperature` и `num_ctx` из Day 29 этот клиент не отправляет, и Day 32 его не меняет.

Индекс Day 31 в `day31/index/docs.sqlite` ревьюер сам не читает: он мог быть собран на другой ветке. Свой снимок лежит в `day32/index/`.

## Индекс

Команда читает дерево `HEAD` через `git ls-tree` и `git show`. Несохранённые правки в рабочую копию индекса не попадают.

```bash
cd ~/Projects/ai-advent-9
.venv/bin/python -m day32.index_code
```

Повторный запуск заменяет `day32/index/docs.sqlite` и `day32/index/code.sqlite`. Одинаковый `chunk_id` второй раз не пишется. Рядом лежит `manifest.json` с полным commit. Каталоги `day32/index/` и `day32/reports/` в `.gitignore`.

В код попадают только `.py` проекта. Не индексируются `.env`, ключи, `.git`, `.venv`, кэши и файлы с NUL.

Если `--head` указывает на другой commit, чем записан в manifest, RAG в этот прогон не подмешивается. В отчёте есть фраза «не смешать версии». Нужно снова выполнить `python -m day32.index_code` на нужном commit.

## Локальный запуск

Ollama должна слушать `127.0.0.1:11434`, модель `qwen3:8b`.

```bash
cd ~/Projects/ai-advent-9
.venv/bin/python -m day32.index_code
.venv/bin/python -m day32 --base main --head HEAD
```

`--repo` по умолчанию текущий каталог, `--output` по умолчанию `day32/reports`. Печатаются число файлов, сколько из них не вошло в анализ, число документов и кусков кода, счётчики severity и пути к `review.md` и `findings.json`.

Лимиты, их видно в отчёте, а не тихий обрез:

- один diff длиннее 12000 символов не отправляется целиком;
- суммарно в анализ идёт не больше 48000 символов diff;
- не больше 40 файлов;
- бинарные файлы и секреты (`.env`, `*.pem`, `id_rsa`) в модель не отправляются.

Пустой diff модель не вызывает. Нет текстовых изменений — в итоге так и написано.

Живой прогон Qwen, его автотесты не делают:

```bash
.venv/bin/python -m day32.check_review
```

Он сравнивает `HEAD~1` и `HEAD`.

## Как проверяются замечания

Модель должна вернуть JSON. Для каждого пункта программа проверяет:

- `severity`: critical, high, medium, low;
- `category`: bug, architecture, recommendation;
- `file` есть среди проанализированных путей diff;
- `line` попадает в hunk новой версии, а для удалённого файла — в старую сторону hunk;
- `evidence` короче 12 символов не принимается; более длинная цитата должна совпасть с diff или с приложенным фрагментом после схлопывания пробелов.

Иначе пункт отбрасывается и в Markdown не выглядит как найденная ошибка. Если после проверки список пуст, итог: «Существенных проблем не обнаружено.» Догадка модели этот текст не заменяет.

`bug` — сценарий ошибки виден в diff. `architecture` — расхождение с контрактом или границей модуля, это не доказанный сбой. `recommendation` — тест, читаемость, упрощение, риск производительности.

## Пример отчёта

Это форма, не результат прогона по этому репозиторию.

```markdown
# Code review

Base: `main` `abc123`
Head: `HEAD` `def456`

## Изменения
- modified `pkg/mod.py`

## Не вошло в анализ
- `pic.bin`: бинарный файл

## Замечания
### high · bug · `pkg/mod.py` · line 4

Деление на ноль.

Почему: Вызов всегда бросает ZeroDivisionError.

Что сделать: Верните число или обработайте ноль.

Evidence: return 1 / 0

## Итог

Проверенных замечаний: 1.
```

## GitHub Actions

Файл `.github/workflows/day32-review.yml` запускается на `pull_request`: opened, synchronize, reopened. События `pull_request_target` нет.

Нужен self-hosted runner с меткой `ollama`. На нём Ollama слушает только `127.0.0.1:11434`. В интернет её открывать не нужно. Секретов у job нет. Права: `contents: read` и `actions: write` для artifact. Комментарий в PR не пишется, merge и блокировка по тексту модели не делаются.

Job пропускает PR из форка. Он забирает head PR и выполняет код репозитория, включая `python -m day32`. Для публичных PR от незнакомых участников так делать нельзя: workflow из PR тоже может быть изменён. Пока runner не изолирован и не зарегистрирован, автоматический запуск не включён.

На GitHub этот workflow не запускался. Локальная проверка — команды выше и автотесты.

Краткое резюме в Step Summary и Markdown в artifact `day32-review` появятся только после реального прогона.

## Тесты

Ollama в автотестах заменена. Git выполняется во временном репозитории.

```bash
.venv/bin/python -m unittest discover -s day32 -p 'test_*.py' -v
```

Прогон: 20 тестов, все прошли. Покрыты diff, пустой диапазон, удаление, переименование, бинарный файл, большой diff, секрет, плохой ref, индекс из commit, а не из грязной копии, повторная индексация, устаревший индекс, принятое замечание, выдуманные файл и строка, prompt injection, чужой evidence, отказ Ollama, пустая документация и ограничения workflow. Живой Qwen и GitHub Action не запускались.

## Риски

- Qwen может описать правдоподобный баг. Без совпадения цитаты и строки отчёт его не покажет, но и настоящий баг без точной цитаты пропадёт.
- Совпадение по первым пяти буквам в поиске Day 31 не понимает смысл. Контекст может быть соседним, а не тем самым контрактом.
- Self-hosted runner с checkout PR исполняет код PR. Это приемлемо только для своих веток.
- Облачная модель не используется. Если Ollama на runner не запущена, job завершится ошибкой соединения, а не замечаниями.
