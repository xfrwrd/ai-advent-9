# Day 30 — локальная LLM как приватный сервис

Mac принимает чат по HTTP и отвечает через Ollama на `127.0.0.1:11434`. В облако сообщения не уходят. Ollama этот сервис не перенастраивает.

```text
Телефон или curl
    ↓  Bearer token, только если включён LAN
FastAPI 127.0.0.1:8030
    ↓  история сессии в памяти, не больше 2 генераций сразу
Ollama 127.0.0.1:11434
    ↓
qwen3:8b
```

История хранится в памяти процесса. После перезапуска она пропадает. Сессий не больше 100, в каждой не больше 20 реплик, тишина дольше 30 минут удаляет сессию. Знать `session_id` недостаточно: первое сообщение выдаёт `session_token`, следующее должно прислать заголовок `X-Session-Token`. Чужой токен получает 403 и текст истории не видит.

## Endpoints

| Метод | Путь | Ключ | Что делает |
| --- | --- | --- | --- |
| GET | `/health` | нет | процесс жив |
| GET | `/ready` | да | Ollama отвечает и модель есть в списке |
| POST | `/chat` | да | сообщение и ответ |
| GET | `/metrics` | да | счётчики запросов, без текста сообщений |

`/chat` принимает `session_id` и `message`. В ответе есть `answer` и `session_token`.

Параметры генерации по умолчанию взяты из optimized-конфигурации Day 29: модель `qwen3:8b`, temperature `0.1`, `num_predict` `512`, `num_ctx` `4096`, thinking выключен. Их меняют переменные окружения, не код Day 29.

## Окружение

Токен только в окружении. В git и в примеры его не кладите.

```bash
export DAY30_API_KEY='свой-длинный-токен'
```

Необязательно: `DAY30_MODEL`, `DAY30_TEMPERATURE`, `DAY30_NUM_PREDICT`, `DAY30_NUM_CTX`, `DAY30_TIMEOUT`, `DAY30_OLLAMA_URL`, `DAY30_PORT`.

## Запуск на этом Mac

```bash
cd ~/Projects/ai-advent-9
export DAY30_API_KEY='свой-длинный-токен'
.venv/bin/python -m day30
```

Слушает `127.0.0.1:8030`. Так и оставляйте, пока запрос не нужен с другого устройства.

Страница чата — во втором терминале, с тем же ключом. Она вызывает этот сервис и сама подставляет `session_token`.

```bash
export DAY30_API_KEY='свой-длинный-токен'
.venv/bin/streamlit run day30/ui.py
```

Проверка:

```bash
curl -sS http://127.0.0.1:8030/health

curl -sS http://127.0.0.1:8030/ready \
  -H "Authorization: Bearer $DAY30_API_KEY"

curl -sS http://127.0.0.1:8030/chat \
  -H "Authorization: Bearer $DAY30_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"session_id":"demo","message":"Объясни goroutine простыми словами"}'
```

Второе сообщение той же сессии. Подставьте токен из первого ответа:

```bash
curl -sS http://127.0.0.1:8030/chat \
  -H "Authorization: Bearer $DAY30_API_KEY" \
  -H "X-Session-Token: ВСТАВЬТЕ_SESSION_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"session_id":"demo","message":"А чем она отличается от потока?"}'
```

Без ключа сервис отвечает 401:

```bash
curl -sS -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8030/chat \
  -H 'Content-Type: application/json' \
  -d '{"session_id":"demo","message":"привет"}'
```

## Rate limit и очередь к модели

Не больше 10 запросов в минуту с одного адреса на `/chat`, `/ready` и `/metrics`. Дальше HTTP 429 и заголовок `Retry-After`. Одновременно к Ollama идут не больше 2 генераций. Третья не ждёт в очереди и получает 503.

Длинное сообщение не обрезается. Если оценка размера больше окна, ответ HTTP 413. Оценка — около 3 символов на токен, как в Day 29. Это не токенизатор модели. При `num_ctx` 4096 и `num_predict` 512 одно сообщение длиннее примерно 10 тысяч символов отклоняется.

## Сеть

Локальный IP Mac:

```bash
ipconfig getifaddr en0
```

LAN включается только явно, во втором терминале, после остановки обычного запуска:

```bash
export DAY30_API_KEY='свой-длинный-токен'
export DAY30_LAN=1
.venv/bin/python -m day30
```

Процесс слушает `0.0.0.0:8030`. С телефона в той же Wi-Fi сети:

```bash
curl -sS http://IP_MAC:8030/health
```

Чат с телефона — тот же `curl` на `http://IP_MAC:8030/chat` с заголовком `Authorization`. HTTP без TLS здесь только для своей сети на время урока. Для чужой сети нужен VPN, а не проброс порта на роутере. Роутер и firewall этот проект не трогает.

Ollama должна остаться на `127.0.0.1:11434`. С телефона `http://IP_MAC:11434` открываться не должен. Проверка на Mac:

```bash
lsof -nP -iTCP:11434 -sTCP:LISTEN
```

В колонке адреса ожидается `127.0.0.1:11434`. Выключить LAN: остановить процесс и запустить снова без `DAY30_LAN`.
