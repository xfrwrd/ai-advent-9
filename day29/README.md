# Day 29 — оптимизация локальной LLM

Цель — сравнить два способа вызова уже установленной `qwen3:8b` на одном и том же RAG-контексте Days 21–24. Optimized не объявлен лучше baseline: ответы модели в этом репозитории ещё не прогонялись.

## Baseline

Это вызов из Day 28, `day28/llm.py`: `POST /api/generate`, модель `qwen3:8b`, `stream: false`, `think: false`. Поля `options` нет.

Карточка модели на этой машине, Ollama 0.35.1, прочитана через `/api/show` и `/api/tags`:

- файл GGUF, семейство qwen3, 8.2B параметров;
- квантование `Q4_K_M`, размер 5 225 388 164 байта;
- максимальный контекст модели 40960;
- thinking в карточке по умолчанию `true`, допустимы `false` и `true`;
- в Modelfile заданы `temperature 0.6`, `top_k 20`, `top_p 0.95`, `repeat_penalty 1`;
- `num_ctx` и `num_predict` в Modelfile нет;
- переменная `OLLAMA_CONTEXT_LENGTH` не задана;
- в момент проверки `/api/ps` был пуст, поэтому живое окно загруженной модели не наблюдалось.

В исходниках Ollama 0.35.1 незаданное окно выбирается по VRAM: 4096, 32768 или 262144. На 24 GB Mac это правило есть, но лог запущенного сервера с выбранным числом не сохранился, поэтому baseline не записывает конкретный `num_ctx`. `num_predict` в `DefaultOptions` этой версии равен `-1`.

Шаблон baseline — `GROUNDED_SYSTEM` из `day24/ground.py`. Сообщения склеиваются так же, как в Day 28: `ROLE` и текст.

## Optimized

Отдельная конфигурация, стартовая, не результат замера:

- `think: false` — иначе токены рассуждения съедают `num_predict`;
- `temperature: 0.1`;
- `num_predict: 512`;
- `num_ctx: 4096`;
- отдельный промпт `OPTIMIZED_SYSTEM` в `day29/prompts.py`.

Промпт требует ответ на языке вопроса, факты только из `CONTEXT`, явный отказ при нехватке данных, короткий ответ и цитаты только с уже существующими `chunk_id`. Документы в контексте помечены как данные, а не как инструкции. Старый шаблон Day 24 не заменён.

Пять полных фрагментов по 2000 символов дают промпт около 11109 символов, грубо 3703 токена при 3 символах на токен. В окно 4096 сам промпт помещается, промпт плюс 512 токенов ответа — нет. Это оценка по символам, не токенизатор модели. Если ответ обрежется, окно нужно увеличить отдельным экспериментом.

## Квантование

Установлен только `qwen3:8b` уровня `Q4_K_M`. Другого квантования этой модели в Ollama нет. Более тяжёлый тег, например Q8, пришлось бы скачивать отдельно: это другой файл, больше RAM, и исходная модель была бы не затронута. Скачивание не запускалось. Смена `temperature` квантованием не является.

## Сравнение

Для каждого вопроса поиск Day 22–23 выполняется один раз. Baseline и optimized получают одни и те же оставшиеся фрагменты. Rewrite моделью в это сравнение не входит: иначе два режима могли бы переписать вопрос по-разному. Режимы запускаются по очереди, не параллельно.

Вопросы:

1. Факт: `Чему равен CHUNK_SIZE_CHARS в day21 config?`
2. Несколько фрагментов: порядок `get_tasks`, `summarize_tasks`, `save_summary` и файл сводки.
3. Ответа нет: телефон дежурного в oncall-ротации.
4. Дословная цитата transport из day16.
5. Три условия day21: embedding model, `EMBEDDING_DIM`, `CHUNK_SIZE_CHARS`, и явный пробел, если чего-то нет.

На вопросе 3 порог Day 23 может отсечь все фрагменты. Тогда оба режима возвращают фиксированное «Не знаю» и модель не вызывается. Это общий guard Day 24, а не разница промптов.

Скрипт пишет JSON с временами retrieval, generation и total, счётчиками токенов Ollama, `load_duration`, `eval_duration`, tokens/s и полями `size` / `size_vram` из `/api/ps`, если они пришли. Холодный старт отмечается, когда `load_duration` не меньше 1 секунды. Если `/api/ps` недоступен, память остаётся пустой и не подменяется числом.

Оценки 1–5 заполняются вручную: правильность, соответствие источникам, полнота, следование инструкциям, корректный отказ. Модель сама себя не оценивает. Таблица в `day29/data/results.json` пока пустая.

Вывод по качеству и скорости ответов сделать нельзя: прогоны не выполнялись.

## Видео

1. Откройте страницу, модель **Local**, конфигурация **Baseline**. Покажите строку параметров: think false, temperature не передаётся.
2. Фраза 1, **Спросить**. Дождитесь ответ, sources и времена.
3. Переключите на **Optimized**, не меняя фразу, снова **Спросить**. Контекст тот же. Покажите temperature 0.1, num_predict 512, num_ctx 4096 и вторую колонку.
4. Фраза 3. Обе колонки должны сказать «Не знаю», если поиск ничего не оставил.
5. Поставьте оценки ползунками. Не говорите, что optimized быстрее или точнее, пока таблица в `results.json` пустая.
