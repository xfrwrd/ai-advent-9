# Архитектура проекта

Корень — Git-репозиторий `ai-advent-9`. Папки `day01`–`day30` уже были в дереве до Day 31. Отдельной базы вроде PostgreSQL или Redis в этих днях нет. Docker для них не используется.

## MCP, дни 16–20

Локальные MCP-серверы говорят по stdio.

- `day16/server.py` — демонстрационные инструменты `add`, `echo`, `greet`. Git там нет.
- `day17`–`day19` — чтение задач из локального Task API, сводка и запись JSON. Клиент `day19/mcp_client.py` открывает сессию и вызывает `call_tool`.
- `day20` — два сервера, `task_server` и `history_server`. Реестр `day20/registry.py` запоминает, какой сервер владеет инструментом.

Инструмента текущей Git-ветки в этих серверах нет. В `day10/agent.py` слово branch означает ветку диалога в JSON, а не `git branch`.

## RAG, дни 21–25

Индексация кода и текстов проекта живёт в Day 21 и в Day 31 не пересобирается.

- Чтение файлов: `day21/documents.py`. Туда входят `.md`, `.txt`, `.py`. Каталоги `.venv`, `.git`, `__pycache__` пропускаются.
- Нарезка: `day21/chunking.py`. Фиксированное окно — 2000 символов, перекрытие 200. Структура режет Markdown по заголовкам, Python по `class` и `def`.
- Вектор: `day21/embeddings.py`, модель `local-token-hash-v1`, размерность 256, без API.
- Хранилище: SQLite `day21/index/structure.sqlite` и `day21/index/fixed.sqlite`. Повторная запись заменяет файл целиком.
- Поиск: `day22/retrieve.py`. Сначала BM25 по пути, разделу и тексту, косинус hash-вектора только как запасное сравнение. Совпадения hash-векторов возможны, поэтому одного косинуса недостаточно.
- Day 23 отбрасывает слабые попадания порогом 9.5.
- Day 24, если после порога фрагментов не осталось, возвращает фиксированный ответ и не вызывает модель. Цитата сохраняется только если её текст есть внутри chunk.
- Day 25 — страница диалога поверх этого RAG.

## Локальная модель, дни 26–29

`day26/client.py`, класс `LocalLLMClient`, отправляет `POST /api/generate` на `http://localhost:11434`. Модель по умолчанию `qwen3:8b`. Поле `think` уходит в запрос только если его передали. Day 28 вызывает локальную модель с `think=False`, чтобы рассуждение не занимало ответ.

Day 27 — страница `day27/app.py` и CLI. Вопрос идёт в Ollama напрямую, без Day 30.

Day 28 берёт тот же индекс Day 21. Переключатель Local вызывает Ollama. Переключатель Cloud вызывает DeepSeek через `day22/llm.py`. Локальный режим в облако не ходит.

Day 29 сравнивает два набора параметров генерации. Оптимизированный набор: temperature 0.1, `num_predict` 512, `num_ctx` 4096, `think` выключен. Это настройка запроса, а не новый индекс.

## Приватный сервис, день 30

`day30/app.py` — FastAPI. По умолчанию слушает `127.0.0.1:8030`. Ollama остаётся на `127.0.0.1:11434`.

- `GET /health` без ключа.
- `GET /ready`, `POST /chat`, `GET /metrics` требуют `Authorization: Bearer`. Ключ читается из `DAY30_API_KEY`.
- История сессии хранится в памяти процесса. Кроме `session_id` нужен `session_token`.
- Не больше 10 запросов в минуту с одного адреса и не больше двух генераций одновременно.

Запуск:

```bash
export DAY30_API_KEY='свой-длинный-токен'
.venv/bin/python -m day30
```

Страница этого сервиса: `day30/ui.py`.

## Ассистент, день 31

`/help` не заменяет Day 21 и не индексирует исходники `.py`. Его индекс — корневой `README.md`, `docs/**/*.md`, `day*/README.md` кроме `day31/README.md`, и описания API, если они лежат в `docs`. Свой README Day 31 в индекс не входит: там перечислены учебные вопросы. Файла OpenAPI в репозитории нет.

Поиск переиспользует `day22/retrieve.py` и `LocalHashEmbedder`. Ответ по документации пишет `LocalLLMClient` с `think=False`. Текущую Git-ветку возвращает отдельный MCP-инструмент `git_current_branch` из `day31/mcp_server.py`. Обработчик `/help` сам Git не вызывает.

Инструменты этого сервера только читают: ветка, `git status`, короткая сводка diff, список файлов, которые уже отслеживает Git. Push, reset, checkout и удаление файлов туда не входят.
